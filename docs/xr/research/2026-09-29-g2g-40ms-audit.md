Independent audit, offline only: no ssh, no adb, no DPS, no COM ports. Everything below comes from files in this repo,
the OpenIPC repo (`c:/xampp/htdocs/openipc-low-latency-and-others-video`) and the rig repo
(`c:/Users/vlad_/Documents/Arduino/latency_test`). Keywords: G2G audit, glass-to-glass 40 ms, latență 40 ms, ce setare

## 0. Short answer

1. **Nothing in the race path was found set wrong.** The optical rig on the Quest lens measured race (480p167, 2 Mbit/s,
   MCS2, FEC 4/8) at **26.4 / 27.9 / 26.8 ms mean first light (median 25.4–26.4 ms, min 18–20 ms)** in three windows on
   2026-09-29, 04:00–04:55. That is the "20–30 ms". The per-segment budget predicts 26.7–32.0 ms. [PROVEN: §1.1]
2. **The ~44 ms is the HD mode itself** (1080p90 native, 16 Mbit/s, MCS7, FEC 4/8), not an extra cost on top of it.
   Built from measured segments, HD should read **46.5–49.4 ms** on the rig. It reads **43.7–46.0 ms** first light and
   47.4–49.5 ms full light, so the rig is 1–5 ms *below* the prediction, not above it. The +18 ms over race breaks down
   as: frame spread on the radio +7.7, encode +4.1…4.9, readout +3.0, capture phase +2.5, decode +1.4, compositor
   wait +1.0, ISP ~+0.5 ms. [INFERRED: §2]
3. **1080p90 native cannot reach ≤ 40 ms at 16 Mbit/s on this link.** Capture phase, readout and compositor wait at
   90 fps already cost +6.5 ms over race before any bits are sent, and the frame's 8.75 ms spread on the radio does the
   rest. The fastest HD-like option that stays well under 40 ms is **720p120 native at 8–12 Mbit/s, MCS7, FEC 4/8:
   predicted 34–39 ms first light.** 1080p90 at 8 Mbit/s MCS7 is marginal (38–41 ms). [INFERRED: §4]
4. **One unresolved regression signal, worth ~3 ms.** The only race rig sample taken after the evening changes
   (ch 165, APK c8986061, a new sensor spot on the lens) read **29.6 ms mean / 29.4 ms median, n = 7**, against
   26.4–27.9 ms in the morning. HD read +1.5 ms higher in the same session. Four things changed together, and n is
   small. The slot in §5 separates them. [PROVEN numbers, cause SPECULATION: §3.2]
5. **Two setting-level costs that are real but small, and one latent risk:**
   - **Menu labels.** The Balanced, Balanced-lite and Wide bundles send **4000 kbit/s**, but their G2G labels were
     measured at 2000. Expect about +1.5…1.7 ms over the label.
   - **HD preset input buffer.** The HD preset's `rcvbuf=524288` (1 MB effective) costs +0.4 ms mean and +4 ms p95
     while the link keeps up. Over capacity it becomes a standing queue of about +250 ms. §3.1 rows 3 and 8.

Two premise corrections:
- **The rig has run in race.** It did so four times: the "after" windows of three rmem runs and the saturation gate
  (§1.1).
- **"20 ms" was never a Quest number.** The 20 ms target was reached on the HIL ground station with a 240 Hz monitor
  (OpenIPC `docs/KNOWLEDGE.md:21`). The Quest 2 panel alone costs ~10–13 ms (`g2g-budget.md:15`), so race on the Quest
  sits at 25–28 ms.

- **Predicted rig first light for HD** = race rig 26.4…27.9 + Δ 20.1…21.5 = **46.5–49.4 ms**. Measured:
  **43.7–46.0 ms** first light, 47.4–49.5 ms full light (§1.1). The measurement is 1–5 ms under the prediction.
  That fits "first light" catching the partly exposed frame, which shrinks the 90 fps capture-phase term, and the ISP
  and panel terms sitting low. A hidden wrong setting would push the rig above the prediction, not below
  [INFERRED].
- **The measured race → HD difference, +17.5…19.3 ms**, same rig, same sessions (first-full-light README:108;
  rmem-ab README:42), is smaller than the +20…21.5 ms of summed segments. Neither the mode switch nor any HD setting
  adds unexplained milliseconds [INFERRED].
- **The frame spread is pure airtime.** 16.8 data packets per frame + 16.8 parity at FEC 4/8 ≈ 33.6 packets per frame,
  2930 pkt/s on air [PROVEN `link-envelope.md:541`]. The queue knee at MCS7 long GI is 3400–3700 pkt/s
  [INFERRED `link-envelope.md:556`], so each packet costs ~0.27–0.29 ms including overhead, and ~32 intervals
  ≈ 8.7 ms, which matches the measured 8.75 ms [INFERRED]. HD runs at ~80–86 % of the knee. Any scene change (a
  ~55-packet frame ≈ 110 packets on air ≈ 30 ms) therefore queues the following frames, which is the p95 tail (Quest
  last95 ~20 ms with the rig flashing, `big-frames-…rmemrig.txt:12`).
- **HD at a lower MCS is a different mode.** MCS5 at 16M costs +9…11 ms mean and +21 ms p95 over MCS7, because it is
  near the knee [PROVEN `link-envelope.md:505-506`]. The HD bundle pins MCS7 with `alink=0`
  (`vmoded.conf:58`), so this does not happen by itself.

## 4. Q3: the fastest configuration ≤ 40 ms with HD-like quality

Method:
- **Anchor on a rig reading of the same family.** Race rig for the 480p/720p modes, HD rig for the 1080p90 variants.
- **Add measured segment differences.** W3c budgets for the modes; the airtime model for bitrate/MCS.
- **Airtime model:** spread ≈ (d − 1) · (n/k) · t_pkt, where d = data packets per frame
  ≈ 16.8 · (kbps/16000) · (90/fps), and t_pkt = 0.273 ms at MCS7 long GI. t_pkt is calibrated on the measured
  8.75 ms at d = 16.8 [PROVEN input, INFERRED model].
- Encode at a higher bitrate is not measured: +0…1 ms [SPECULATION].

| Candidate | pkt/s on air | spread | Predicted rig first light | ≤ 40? | Notes |
|---|---|---|---|---|---|
| race 480p167 2M MCS2 (today) | ~600 | 1.05 | **25.4–27.9 measured** | yes | narrow crop, 33 × 44 % |
| balanced-lite 720p120 → 848×480, 2M | ~500 | 1.24 | 31.3–32.8 | yes | 66 × 66 %, ~1.5× softer than race |

- **Recommendation for an "HD-like ≤ 40 ms" preset:**
  - **720p120 native at 8 Mbit/s, MCS7, 1SS STBC, FEC 4/8, no `-R`.** Predicted 34–37 ms first light, about −8…10 ms
    against HD [INFERRED].
  - 12 Mbit/s buys more detail at about +2 ms.
  - MCS7 needs ≤ 20 dBm and a short range (`option-costs.md:93`).
  - With alink on, the MCS must not fall to MCS4/5 at 8–12 Mbit/s: MCS5 near the knee cost +9…11 ms at 16M.
- **What 1080p90 cannot escape:** 90 fps costs +2.5 ms of capture phase, +3.0 of full-height readout and +1.0 of
  compositor wait over race, plus ~4 ms more encode than 720p. Even with zero spread, 1080p90 native would read about
  35–36 ms [INFERRED: HD rig − 8.75 + 0.3].

## 5. Q4: measurement plan for one rig slot (~50 min)

**Goal:** separate "the mode costs it" from "a setting costs it". Keep every physical thing fixed.

**Setup:**
- Quest ≥ 1 m from the air unit, awake (`guardian_pause 1` + `prox_close`), XR running on ch165.
- Rig sensor untouched for the whole slot.
- **Calibrate once in the dimmest mode (HD)**, so full light is reachable everywhere. First light does not depend on
  the calibration maximum.
- Stamp `date +%s.%N` before and after each rig run. Label steps by the air's `SET` epochs, not the plan
  (saturation-gate README correction).
- Each run is 25 flashes (~40 s). Drop ±3 s around every switch.
- Record per step: `/tmp/linkmode-bcn.log`, `isp_pin.sh status`, `wfb_tx` argv (`ps`), `wfb_tx_cmd 9000 get_radio/get_fec`,
  and the Quest's `RefreshWatch` line (all read-only).

**Part A: modes, everything else fixed (N = 2, palindromic A B C D D C B A, ~16 runs)**

| State | Config | Predicted first light | A setting is suspect if |
|---|---|---|---|
| A race | 480p167 2M MCS2 FEC 4/8 | 25.5–27.9 | > 30 |
| B balanced | 720p120 native 2M MCS2 FEC 4/8 | 32.7–34.2 | > 36 |
| C HD-lite | 720p120 native 8M MCS7 FEC 4/8 | 34–37 | > 39 |
| D HD | 1080p90 16M MCS7 FEC 4/8, **no -R** | 43.7–46.0 | > 48 |

- **Rule:** if every state lands inside its prediction ±2 ms, the mode explains the latency. A state > 3 ms above its
  prediction points at a setting in that state's own path.
- Every switch restarts waybeam. The rig is immune to the new RTP base; Quest traces can only be compared within one
  state.

**Part B: live levers inside one waybeam instance (no restart, so Quest capture→decoded deltas are valid too; N = 2, ABAB)**

- In D: bitrate 16 → 8 Mbit/s (waybeam API; json is RAM-linked since O114). Predicted −4.9 ms spread, rig ~−5 ms.
- In D: FEC 4/8 ↔ 8/12 (`wfb_setfec`). Predicted −2.3 ms spread and more loss.
- In A: MCS2 ↔ MCS7 (`wfb_tx_cmd 9000 set_radio`, all fields). Predicted −0.6 ms.

**Part C: the suspects behind the evening +3 ms (race, N = 2, ABAB each, ~15 min)**
